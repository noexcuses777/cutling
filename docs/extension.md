# Chrome 확장 프로그램

MV3 서비스 워커, 네이버 content script, 웹 연결 bridge, popup, options를 실제 번들로 빌드합니다. Chrome 120 이상에서 압축 해제 확장 프로그램으로 설치합니다.

## 설치와 연결

1. 프로젝트 루트에서 `pnpm install` 후 `pnpm build:extension`을 실행합니다.
2. 자료 저장 기능도 쓰려면 `pnpm dev`로 웹을 실행합니다. 기본 검색 필터에는 서버나 프로젝트가 필요하지 않습니다.
3. Chrome에서 `chrome://extensions`를 열고 개발자 모드를 켭니다.
4. ‘압축 해제된 확장 프로그램 로드’로 `apps/extension/dist` 폴더를 선택합니다.
5. 네이버에서 검색하고 새로고침합니다. 기본 필터는 바로 켜지며 광고와 검색어에서 벗어난 결과를 흐리게 접습니다.
6. 자료 저장과 프로젝트 연동을 사용하려면 웹 서비스의 설정에서 일회용 연결 코드를 발급합니다.
7. 확장 아이콘 → 연결 설정에서 기본 서버 주소를 확인하고 코드를 입력합니다.
8. 이미 열려 있던 웹 페이지를 새로고침합니다. 웹에서 ‘네이버에서 검색’을 누르면 실제 검색 탭에 프로젝트가 연결됩니다.
9. 직접 연 네이버 탭은 현재 검색어를 기준으로 필터링합니다. 저장할 때는 패널이나 확장 popup에서 프로젝트를 선택합니다.

기존 설치 업데이트: `chrome://extensions`의 **Cutling · 커틀링** 카드에서 새로고침(원형 화살표)을 누른 뒤 네이버 검색 탭도 새로고침합니다. 설치 폴더를 옮기지 말고 같은 위치의 새 번들을 사용하세요. Sources의 워크스페이스 추가는 필요하지 않습니다.

웹과 확장 프로그램은 같은 API·프로젝트·자료·로드맵·이벤트 데이터를 사용합니다. 사용자 자료는 브라우저 저장소가 아닌 서버 DB에 저장됩니다. `pnpm dev:extension`은 번들을 감시하며, 변경 후 Chrome 확장 관리 화면에서 새로고침하고 네이버 탭도 새로고침해야 합니다.

## 지원하는 동작

- `search.naver.com`의 `query` 감지 및 변경 감시
- 일반 결과와 Powerlink 광고 영역의 구조에서 제목·요약·URL·표시 날짜·명시적 광고 표시 추출
- 화면에 보이는 결과만 최대 10개씩 분석. 자동 원문 방문 없음
- 연결 없이 규칙 기반 필터 즉시 적용. 연결된 프로젝트에서는 서버 결과·정밀 작업 결과를 점진 적용
- 검색어·목적·필터가 바뀌면 버전을 올려 오래된 응답 무시
- 광고·관련 없는 결과를 흐린 미리보기와 짧은 접힌 영역으로 표시. 원래 링크·노드는 보존하고 다시 보기 또는 필터 OFF 시 높이와 스타일 복원
- 다시 보기, 유용함, 사이트 항상 보기, 해당 유형 덜 가리기, 재평가 요청
- Shadow DOM 학습 패널: 의도 칩, 필터, 저장 자료, 로드맵, 다음 검색, 대시보드
- 화면 오른쪽에 충분한 여백이 없으면 기본으로 접힌 버튼. 좁은 화면에서 펼치기는 사용자가 요청
- 네이버 블로그에서 popup ‘이 페이지 담기’로 현재 공개된 본문을 읽어 저장. `se-main-container`, `postViewArea` 등 지원; iframe의 블로그 본문에도 적용

## 권한과 보안

필수 호스트는 네이버 검색·블로그와 로컬 개발 서버 호스트뿐입니다. `tabs` 전체 권한 대신 `activeTab`과 해당 호스트 권한을 사용합니다. Chrome의 localhost match pattern은 호스트 범위를 표현하므로, 워커와 bridge는 기본 `http://localhost:3000` 또는 설정한 `http://127.0.0.1:3000` origin을 정확히 검사합니다. 다른 로컬 포트에서 보낸 bridge 요청은 거부합니다.

별도 HTTPS 서버를 쓰면 options에서 그 주소를 직접 입력하고 ‘서버 주소 저장’을 눌러 해당 origin 권한만 요청합니다. manifest의 `optional_host_permissions`에 선언한 HTTPS wildcard는 설치 시 부여되는 상시 접근 권한이 아닙니다. 웹 연결 content script도 선택한 origin 하나에만 동적으로 등록됩니다. 주소를 바꾸면 연결 토큰을 제거하고 재연결을 요구합니다.

연결 토큰은 Chrome trusted contexts로 제한된 local storage에만 보관합니다. content script와 웹에는 토큰을 반환하지 않습니다. 웹 bridge는 동일 창·정확한 origin·최상위 frame·메시지 종류·request ID를 검증하고 ‘연결 상태’와 ‘검색 열기’만 전달합니다. 본문·제목·모델 응답은 `textContent`로 렌더링합니다. 원격 HTML과 코드를 실행하지 않습니다. 서버의 소유권 검사와 토큰 만료 검증도 별도로 적용됩니다. Chrome의 권한 있는 GET 요청은 Origin을 생략할 수 있어, 워커가 전달하는 확장 ID와 서버의 토큰 발급 대상 ID를 추가로 대조합니다. Origin이 존재하면 일치 여부를 반드시 검사합니다.

Chrome 권한 기준: [공식 match patterns 문서](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns), [공식 optional permissions 문서](https://developer.chrome.com/docs/extensions/reference/api/permissions).

## 검증 범위와 제약

0.2.0 추가 검사(2026-10-13): 별도 Chromium 프로필에서 웹에 연결하지 않은 채 실제 네이버의 **딥러닝**을 검색했습니다. Powerlink 광고 **10/10개**가 접히고, 그 아래 관련 있는 일반 검색 결과는 유지됨을 확인했습니다. [최신 검사 기록](screenshots/naver-live-checks.json), [접힌 광고 화면](screenshots/naver-live-desktop.png), [유지된 일반 결과](screenshots/naver-live-results.png). 관련 없는 글·다시 보기·필터 끄기·동적 결과는 합성 검색 통합 검사로 별도 확인합니다.

연결 상태 확인은 전체 프로젝트 목록을 조회하지 않고 인증 상태만 확인합니다. 성공한 연결·인증 요청의 짧은 검증 기록을 사용하며, 토큰·서버·만료 시각이 바뀌거나 인증이 실패하면 무효화합니다.

자동 테스트에는 **직접 만든 합성 fixture**와 **공개 화면에서 관찰한 구조를 보존하되 제목·요약·URL을 합성 자료로 교체한 SDS fixture**가 있습니다. 후자는 `packages/search-adapters/fixtures/naver-sds-2026-10.html`이며 해시 CSS 클래스나 출처 원문을 복제하지 않습니다. 테스트 데이터와 실제 네이버 검증은 구분합니다.

2026-10-13 19:35 KST에 headless Chromium에 실제 MV3 번들을 로드하고, 요청 가로채기 없이 공개 네이버의 ‘딥러닝 공부 순서’를 확인했습니다. HTTP 200 응답, 검색어·패널·보이는 결과 2개의 배지, 필터 OFF 복구, 원본 URL 보존, 선택 자료 1건의 서버 저장·조회가 통과했습니다. 실제 화면의 최신 `fds-web-doc-root` / SDS 구조에 맞춰 어댑터를 보완했습니다. [검증 기록](screenshots/naver-live-verification.json)과 [실제 화면](screenshots/naver-live-search.png)을 남겼습니다.

이는 특정 검색어와 시점에 대한 제한된 실화면 검증입니다. 당시 두 결과는 추천으로 분류되어 실제 결과의 흐림·다시 보기는 확인하지 않았고, 해당 동작은 합성 페이지의 실제 확장 통합 테스트에서 통과했습니다. 모든 네이버 결과 유형, 사용자 Chrome 프로필에서의 수동 설치, 실제 네이버 블로그 캡처, 장시간 스크롤·검색 반복, live HCX 호출은 아직 실환경에서 확인하지 않았습니다. DOM이 바뀌면 일부 블록을 건너뛰며, 결과가 없다고 분석 성공으로 표시하지 않습니다. 어댑터는 `packages/search-adapters/src/index.ts`에서 갱신합니다.

블로그 공개 DOM을 찾지 못하거나 접근이 제한된 경우 웹에서 URL 또는 본문을 직접 입력합니다. 로그인·캡차·유료 접근을 우회하지 않습니다. 현재 페이지 캡처는 서버 API와 같은 최대 40,000자이며 한도를 넘으면 일부 본문임을 알립니다. 다른 일반 사이트의 DOM 캡처는 아직 지원하지 않지만 웹 URL 저장은 지원합니다.

## 실제 네이버 수동 확인 체크리스트

- [x] 빌드된 dist를 Chromium에서 로드하고 웹 연결 코드로 연결 (headless 자동 검증)
- [x] ‘딥러닝 공부 순서’에서 검색어·프로젝트·패널 확인
- [ ] 보이는 결과의 배지 및 흐림, 이유와 근거 범위 확인
- [ ] 원문 링크와 키보드 탐색이 계속 정상 동작
- [ ] 다시 보기·사이트 항상 보기·유용함 피드백
- [ ] 스크롤 후 새 결과만 분석하고 자기 삽입 노드로 루프가 생기지 않음
- [ ] 검색어 또는 의도를 바꾼 뒤 이전 응답이 새 결과에 적용되지 않음
- [x] 필터 OFF 시 배지 제거 및 원래 스타일 복원 (실제 검색 결과)
- [x] 담은 자료를 같은 프로젝트의 서버 API에서 조회 (패널 갱신 확인)
- [ ] 패널의 다음 검색이 같은 프로젝트로 새 네이버 탭을 엶
- [ ] 네이버 블로그 popup ‘이 페이지 담기’, 본문 기반 요약 범위 확인
- [ ] 연결 해제·토큰 만료 후 다시 연결하기 안내 확인

체크되지 않은 항목은 실화면 검증 완료를 의미하지 않습니다.
