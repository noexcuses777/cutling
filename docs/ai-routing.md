# AI 라우팅과 근거

`rules`는 외부 모델 없이 규칙, 발췌 요약, 일반 학습 제안을 제공합니다. `demo`는 명시적으로 선택한 합성 자료와 동일한 로컬 로직을 사용하며 실제 HCX 사용량을 만들지 않습니다. `live`는 서버 설정과 실제 API를 사용하고 오류 시 규칙 결과를 반환합니다. 응답에는 실제 실행 모드, fallback, errorCode가 포함됩니다.

분류 순서는 URL·텍스트 중복 확인 → 광고 구조화 표시와 규칙 → 목적/제목/요약 임베딩 → 애매한 결과의 경량 보완 → 남은 충돌·모호함에 정밀 모델입니다. 결과는 최대 40개, 모델 분류는 배치당 최대 12개로 제한됩니다. 임베딩 v2는 단건 API이므로 동일 입력을 제거한 뒤 최대 동시성 아래 호출합니다. 의도 미확정, 요약 부족, 광고와 학습 목적의 충돌은 강한 필터 대신 review를 유지합니다. 재평가 요청은 정밀 판단 조건입니다.

광고와 관련도는 별도 필드입니다. 부트캠프 비교 목적에서는 모집 결과가 관련 자료일 수 있으며 취업 후기 목적에서는 후기를 자동으로 낮추지 않습니다. 오래된 벡터·행렬 자료는 기초 개념으로 구분하고 설치·API·버전 관련 자료에만 날짜 경고를 적용합니다. 날짜가 없으면 unknown입니다. 공식 문서 표시는 검증 가능한 공식 문서 도메인 목록에 제한합니다. 무료 표시는 검색 요약이 직접 언급한 콘텐츠 유형일 뿐 실제 가격 검증 결과로 사용하면 안 됩니다.

임베딩 유사도는 확률이 아닙니다. semantic_overlap은 비슷한 주제의 후보이며 본문 복제를 뜻하지 않습니다. 규칙·임베딩 충돌은 review와 정밀 라우팅 근거입니다. `packages/shared/src/classification.ts`의 임계값은 초기 제품 가정이며 fixture를 기반으로 조정할 수 있습니다. 작은 합성 fixture 성능을 네이버 전체 정확도로 표현하면 안 됩니다.

캐시는 서버 메모리의 제한된 TTL 캐시입니다. SHA-256 키에 소유자, 입력, 의도·필터, 모델, 엔드포인트, 프롬프트·스키마 버전을 포함합니다. 최대 500개, 기본 5분이며 재시작하면 사라집니다. 소유자를 전달하지 않으면 인스턴스별 격리됩니다. 개인 필기는 캐시하지 않습니다. 캐시 적중은 새 API 호출이나 토큰 소비로 합산하지 않습니다. 사용자 데이터 삭제에서는 `clearAICache(ownerId)`로 소유자의 캐시를 즉시 지웁니다.

각 네트워크 시도의 역할·모델·요청 ID·지연·성공·오류 코드와 공급자 토큰을 기록합니다. 키·원문·모델 내부 사고 과정은 기록하지 않습니다. 429와 서버 오류만 제한 재시도하며 네트워크 실패와 타임아웃도 최대 재시도 설정을 따릅니다. 인증 오류는 재시도하지 않습니다. JSON 스키마·근거 검증 실패는 한 번만 수정 요청하고 다시 실패하면 로컬 폴백입니다. 요청 취소는 타임아웃 AbortController로 수행하며 검색어 변경의 오래된 응답 무효화는 확장 프로그램 세션 버전으로 수행합니다.

요약은 최대 24개 문단을 모델에 전달합니다. 각 줄에 실제 문단 ID가 존재하는지, 요약이 정확히 3줄인지, evidenceScope가 일치하는지 확인합니다. 텍스트가 짧으면 부족함 안내를 반환합니다. 로컬 요약은 최대 180자짜리 짧은 발췌 3개이며 원문 밖 설명을 생성하지 않습니다. ID 검증만으로 문장의 사실성을 완벽히 증명할 수는 없으므로 원문 확인 링크를 유지합니다.

로드맵은 쿼리·목적·수준에 맞춘 일반 초안과 저장 요약의 개념 연결을 구분합니다. 수학, 파이썬, 머신러닝, 실습, 모집 비교, 취업 후기, 설치 목적에 따라 단계가 달라집니다. 자료가 없는 단계는 draft입니다. 자료 삭제 시 연결을 해제하고 완료 표시·메모를 보존합니다. HCX `updateRoadmap`은 최신 30개 자료의 구조화 요약과 짧은 문단 근거를 정밀 모델에 보냅니다. 기존 단계 ID·순서를 보존하며 연결 자료 ID를 허용 목록과 대조합니다. 완료 표시·메모·제목은 서버가 그대로 보존합니다. 오류 시 동적인 규칙 로드맵으로 돌아옵니다. 초기 `generateRoadmap`은 항상 일반 학습 초안을 명시합니다. 다음 검색은 미완료 단계의 부족한 개념 및 필기 질문에서 생성하며 이미 실행한 검색은 표시합니다. HCX 제안 역시 단계 ID를 검증하고 검색어에 URL을 허용하지 않습니다.

서버는 변경 직후 로컬 로드맵을 저장하고, 연속 변경을 묶은 뒤 HCX 보완을 실행합니다. GET 조회와 완료 체크는 모델을 호출하지 않습니다. 모델 실행 전후 프로젝트·자료의 지문과 로드맵 버전을 비교하고, 짧은 DB 트랜잭션 안에서 최신 완료 상태·메모를 보존합니다. 삭제·목적 변경·새 자료가 생긴 동안의 오래된 응답은 버립니다. 보완된 다음 검색은 저장되어 조회에 재사용됩니다. 연결 진단 역시 현재 키·역할·엔드포인트 지문과 일치할 때만 검증 완료로 표시합니다.

개인 필기에서 파생한 자료는 `externalConsent`가 저장된 경우에만 HCX 로드맵 문맥에 포함합니다. 동의하지 않은 필기의 본문·제목과 사용자 메모는 프롬프트에서 제외하고 단계 연결은 로컬에 유지합니다. OCR 처리 중 수정한 텍스트, 필기 정리 중 변경된 내용, 사용자가 유용하다고 선택한 검색 결과는 늦게 도착한 모델 출력이 덮어쓰지 않습니다. 이전 검색과 아카이브에서 확인한 동일 URL·텍스트 증거도 현재 배치의 AI 결과보다 우선 보존합니다.

필기 정리 동의는 검토한 텍스트의 SHA-256 지문에 연결됩니다. 텍스트를 실제로 수정하면 기존 동의와 이전 정리 결과를 해제합니다. 영속 작업에는 텍스트 지문만 함께 저장하며, 처리 시작 전과 결과 저장 전에 현재 지문·동의를 확인합니다. 대기 중 원문이 변경되면 외부 전송 없이 오래된 작업을 건너뛰고, 새로 동의한 버전은 별도 작업으로 처리합니다.

리포트의 시간은 행동 측정치가 아닌 제품 가정입니다. 다시 펼친 결과를 제외하고 동일 결과의 중복·홍보 분류를 중복 합산하지 않습니다. 실제 비용은 공급자 사용량과 운영자 가격표가 모두 있을 때만 계산합니다. baseline이 없거나 0이면 비교 unavailable, 절감률 null입니다. 비용 증가인 음수 절감률은 보정하지 않습니다. 전체 모델 요청 중 추론 비율과 분류 대상 결과 중 정밀 라우팅 비율은 서로 다릅니다.
