# 5~8분 해커톤 데모

사전 준비: 서버/DB 실행, 확장 빌드·unpacked 설치, 연결 코드로 연결, HCX 사용 시 설정 화면에서 진단. 실제 모델 권한과 요금 확인. 필기 이미지 하나 준비. 네이버 결과는 매번 달라질 수 있어 결과 수나 절약 시간을 미리 고정하지 않습니다.

1. 홈에서 "검색부터 학습 시작까지" 가치 설명, 연결 상태 확인.
2. "딥러닝 공부 순서", "처음 시작", "입문 로드맵" 프로젝트 생성 → 실제 네이버 탭 열기.
3. 목적 칩 선택 → 규칙 1차 배지. live를 설정했다면 애매한 결과만 후속 처리되는 상태 확인.
4. 주목도 낮춘 결과의 이유/다시 보기/유용해요를 눌러 사용자 제어 시연. 원문 링크가 유지됨 확인.
5. 자료 3개 담기 → 웹 아카이브에서 저장/본문/요약 상태 확인.
6. 3줄 요약과 원문 문단 근거 확인. 로드맵의 초안·저장 자료 기반 단계 차이와 부족한 개념 검색 클릭.
7. 필기 이미지 업로드 → 로컬 OCR → 원문과 대조·수정 → 정리 → 아카이브/단계 연결.
8. 리포트에서 실제 분석/저장/펼치기 수, 추정 시간 가정, 실제/미제공 모델 usage, 비교 unavailable 구분.

네이버/외부 API가 불안정하면 홈의 샘플 프로젝트를 명시적으로 사용합니다. "지금부터는 재현 가능한 샘플 데이터로 보여 드립니다."라고 알리고 데모 데이터 배지를 확인하세요. fixture는 합성 자료이며 네이버 실제 화면 검증의 대체 증거로 제시하지 않습니다. OCR 실패 시 이미지를 보며 직접 입력, 본문 제한 시 붙여넣기, HCX 실패 시 규칙 폴백으로 흐름을 계속할 수 있습니다.

발표에서 구현한 기능, 실제 검증한 연결, 추정 지표, 앞으로 할 비교 실험을 분리합니다. 작은 fixture를 근거로 완벽한 광고 판별/전체 정확도/비용 절감률을 주장하지 않습니다.
