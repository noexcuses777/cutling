## 화면 정제 및 확장 0.2.0

- 홈을 검색 중심으로 정리하고 흰색 바탕·차콜 본문으로 변경했습니다. 목표·모델·시간 추정·기타 설정은 필요할 때 펼칩니다.
- 프로젝트나 서버 연결 없이 네이버의 현재 검색어로 기본 필터를 실행합니다. 자료 저장·서버 분석은 선택한 프로젝트 연결을 사용합니다.
- Powerlink 광고 영역을 추출하고, 명시적 광고와 관련 없는 결과를 흐린 미리보기로 접습니다. 다시 보기와 필터 끄기로 원래 노드·링크·스타일을 복원합니다.
- 단위·서비스·DOM 회귀 검사 **129개 통과**. Next 프로덕션 빌드, 수정 파일 ESLint, 각 패키지 TypeScript 검사 통과.
- 실제 네이버 `딥러닝` 검색에서 별도 Chromium 프로필에 0.2.0 확장을 로드하고, 연결 없이 Powerlink 광고 **10/10개 접힘**을 확인했습니다. 화면에 들어오는 결과부터 처리하므로 아래 광고는 스크롤하며 확인했습니다. [실화면 검사 기록](screenshots/naver-live-checks.json).
- 운영용 서버의 최종 Playwright E2E **6/6 통과**(52.8초): 미연결 직접 검색, 연결·검색·자료 저장, 데이터 유지, 인증 격리, OCR, 사용자 화면 흐름.
- 합성 검색 통합 검사는 광고/관련 없는 글/관련 학습 자료 구분, 실제 높이 감소, 다시 보기, 필터 OFF/ON, 동적 결과, 서버 요청 없이 실행을 확인합니다.
- 데스크톱·390px 모바일 홈과 설정 등 화면 검사에서 브라우저 예외 0개, 가로 넘침 없음. [화면 검사 기록](screenshots/ui-checks.json).

실제 네이버 검사는 특정 시점·검색어의 공개 화면에 한정됩니다. 사용자 Chrome 프로필의 설치 버전은 별도로 확인하지 않았으며, 기존 설치는 확장 카드와 네이버 탭을 새로고침해야 새 번들을 사용합니다. 보편적인 관련도 정확도나 모든 네이버 레이아웃을 보증하지 않습니다.

마지막 전체 브라우저 검사는 `pnpm build` → `pnpm start`로 실행한 프로덕션 서버에서 수행했습니다. [검증 결과 데이터](verification-results.json)를 함께 제공합니다. 개발 서버의 연결 표시 간헐 실패는 아래에 별도로 남겼으며 최종 프로덕션 검사에서는 재현되지 않았습니다.

단위/통합 검사는 URL·날짜·의도별 분류·중복·로드맵·지표, HCX 응답·오류·usage 누락·캐시·라우팅, SSRF·토큰·소유권, 네이버 DOM·동적 처리·확장 저장 상태를 포함합니다. HCX 테스트는 모의 응답이며 실제 모델 품질 시험이 아닙니다.

E2E에서 실행한 경로:

1. 실제 MV3 번들을 Chromium에 unpacked 로드 → 옵션 연결 → 웹 검색 브리지 → 합성 네이버 화면 배지/흐림/다시 보기/필터 OFF·ON → 자료 저장 → 웹 API 동기화 → 동적 결과 처리.
2. 프로젝트 → 검색 세션/분류 → 자료/근거 요약 → 로드맵/완료 상태 → 새로고침 → 리포트 → 삭제.
3. 일회용 연결 코드 재사용 거부, origin 바인딩, 토큰 폐기, 다른 워크스페이스 접근 거부.
4. 실제 PNG 업로드 → 로컬 `kor+eng` OCR → 원문 수정 → 정리/아카이브 연결 → 이미지 삭제. 마지막 실행은 `status=review`, 텍스트 135자, 한국어 인식 확인. 샘플은 [인쇄체 합성 학습 노트](sample-note.png)이며 임의의 손글씨·수식 인식 정확도는 측정하지 않았습니다. 테스트는 언어 파일 다운로드 실패 때도 수정 가능한 대안을 검사합니다.
5. 홈 화면 기본값으로 프로젝트 생성 → 화면에서 본문 붙여넣기 → 3줄 요약 → 개인 메모 → 로드맵 완료 → 새로고침 후 유지. 이 경로는 준비용 API 호출 없이 UI로 조작합니다.

## 실제 네이버 검증

2026-10-13 19:35 KST, **실제 공개 네이버 검색 페이지**에 headless Chromium과 unpacked 확장을 사용했습니다. 네이버 응답 가로채기나 합성 페이지 대체 없이 `딥러닝 공부 순서` 검색에서 HTTP 200을 받았습니다.

- 실제 검색어 감지, 오른쪽 패널, 현재 SDS 구조의 보이는 결과 2건과 배지 표시 확인.
- 필터 OFF에서 배지 제거와 원래 스타일 복원, 원문 URL 보존 확인.
- 사용자가 선택하는 동작으로 공개 결과 1건을 저장하고 동일 백엔드에서 조회 확인.
- 당시 두 결과가 추천 상태여서 **실네이버 흐림/다시 보기는 미검증**입니다. 해당 기능은 실제 확장을 사용한 합성 검색 E2E에서 확인했습니다.

[검증 기록](screenshots/naver-live-verification.json) · [실제 화면](screenshots/naver-live-search.png)

일반 Chrome의 사용자 프로필에 수동 설치, 네이버의 모든 결과 유형, 블로그 본문 캡처, 장시간 스크롤/검색 변경은 실환경에서 확인하지 않았습니다. DOM 변경과 누락에 대한 테스트는 별도로 있으나 전체 네이버 호환성을 보장하지 않습니다. 수동 확인 항목은 [확장 문서](extension.md)를 따르세요.

## 발견 후 수정한 문제

- 빈 선택 목표의 프로젝트 생성 검증 불일치를 수정하고 UI 경로를 추가했습니다.
- Chrome worker GET이 Origin을 생략하는 경우를 유효 토큰과 연결된 확장 ID 검사로 처리했습니다.
- 분류 갱신 중 자료 저장 버튼이 다시 초기화되는 경합을 수정했습니다. 회귀 테스트와 확장 브라우저 테스트 2회 연속 통과 후 전체 E2E도 통과했습니다.
- Windows의 긴 임시 프로필 경로를 짧은 경로로 바꾸고, 첫 DB 파일 생성 절차를 추가했습니다.
- 실행 중인 개발 서버가 Prisma DLL을 사용하는 동안 엔진 재생성이 실패하는 Windows 제약을 확인했습니다. 빌드 전 개발 서버 종료 방법을 README에 명시했습니다.
- 필기 텍스트가 바뀌면 이전 외부 전송 동의를 해제하고 작업의 텍스트 해시를 다시 확인합니다. 변경된 내용을 과거 동의로 보내거나 오래된 결과가 새 편집을 덮어쓰는 경합을 회귀 검사했습니다.
- 원문 서버가 계속 작은 데이터를 보내도 총 12초 제한이 유지되도록 수집 타이머를 보완했습니다. 리다이렉트 본문 종료와 내부망 이동 차단도 검사했습니다.
- 확장 브리지의 메시지 수신을 즉시 등록하고, 관찰된 약 1초 왕복 지연을 반영해 상태 확인 5초·검색 열기 8초를 기다립니다. 개발 환경 반복 검사 중 한 번은 응답 미확인이 재현되어 정확한 원인은 미확정입니다. 이후 진단을 추가한 반복 2회는 실제 홈 연결 표시까지 통과했습니다. 응답 미확인을 설치 완료/실행 성공으로 표시하지 않으며 설정에서 상태를 다시 확인할 수 있습니다.
