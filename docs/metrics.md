# 실측·추정·비교의 분리

프로젝트마다 모드를 고정합니다. demo와 live/rules 프로젝트를 섞어 합산하지 않습니다. 추천/주목도 낮춤/중복은 겹칠 수 있으므로 항목을 더해 전체 분석 수를 만들지 않습니다. 검색 결과 키는 세션 ID + 원래 result ID라 반복 이벤트로 분석 수를 부풀리지 않습니다. 펼치기는 같은 키 집합으로 중복 제거합니다.

탐색 추정 초 = 다시 펼치지 않은 주목도 낮춤 결과 수 × reviewSeconds(기본 45). 정리 추정 초 = 정리된 자료 수 × organizeSeconds(기본 180). 이 계수는 검증된 행동 데이터가 아닙니다. 중복 검토 시간을 별도 가산하지 않습니다.

모델별 로그는 task, role, model, mode, requestId, 입력/출력 토큰, usageSource, cacheHit, 지연, 성공, 오류 코드를 기록합니다. 프롬프트/키/원문 전문은 로그에 기록하지 않습니다. 토큰이 없는 응답은 null/unavailable입니다. 캐시 응답은 실제 청구 호출 수에서 제외합니다. 실패한 시도에 usage가 없으면 비용은 미상이며 0원이라고 주장하지 않습니다.

정밀 라우팅 비율은 정밀 분류로 전달한 결과 수 / 전체 결과 수입니다. 재시도/재평가가 있을 때 중복 가능성을 주의해야 합니다. 정밀 요청 수 / 모든 API 요청 수와 다른 값입니다.

운영자 가격 예시(숫자는 실제 계약/공식 가격으로 입력):

```json
{"source":"공식 가격표 URL 또는 운영 계약 출처","checkedAt":"YYYY-MM-DD","currency":"KRW","models":{"실제 모델 ID":{"inputPerMillion":0,"outputPerMillion":0}}}
```

이 JSON을 서버 `MODEL_PRICING_JSON`에 한 줄로 입력합니다. 비용 = (입력 토큰 × 입력 백만 토큰 단가 + 출력 토큰 × 출력 백만 토큰 단가) / 1,000,000. 임베딩도 모델별 항목이 필요합니다. 과금 단위가 토큰 외 방식이면 이 계산을 사용하지 말고 미설정으로 두세요. OCR은 로컬 CPU이므로 외부 OCR API 요금이 없으나 컴퓨팅 비용을 계측하지 않습니다.

가격 출처·확인일·필요한 usage 중 하나라도 없으면 비용은 null입니다. 무료 fixture 규칙 평가는 비용 비교가 아닙니다. 유료 전체추론 baseline, 원문 반복 대 요약 재사용, 전체 탐색 작업의 동일 조건 비교는 아직 unavailable입니다. baselineCost가 없거나 0이면 절감률을 계산하지 않습니다. 음수 절감률도 강제로 0으로 바꾸지 않습니다(공유 계산 함수 테스트).
